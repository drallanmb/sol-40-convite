## Assets and trust boundaries

| Asset/boundary | Risk | Mitigation/proof |
|----------------|------|------------------|
| Generated token -> storage | Low entropy or persistent leakage | 32-byte format tests; one sessionStorage key; no URL/localStorage |
| `token_conflict` -> retry helper | Reused hash or retry loop | fresh distinct token, max two calls, automated call-count test |
| Server view -> draft command | Stale overwrite/mass assignment | pure sparse dirty/contact tests |
| Content -> UI | Account/admin spoofing or coercive copy | exact allowed negative phrases; forbidden affirmative-flow tests |
| Dev clock override -> production | Deadline bypass/debug seam shipped live | compile-time DEV guard; production-ignore test; backend remains date-independent |

## High threats

| ID | Threat | Severity | Mitigation | Blocking proof |
|----|--------|----------|------------|----------------|
| T-03-03-A | Capability has weak entropy or persists beyond the browser session. | high | 32 random bytes, base64url, sessionStorage only. | format/storage tests and source scan. |
| T-03-03-B | `token_conflict` reuses the collided token or loops indefinitely. | high | discard collision token; generate one new token; exactly two attempts maximum. | 1/2/no-3 call tests with distinct token assertions. |

| T-03-03-D | Content turns light access into an account/admin flow. | high | only two approved negative phrases; no controls/endpoints/affirmative language. | content tests plus unchanged `/admin`. |
