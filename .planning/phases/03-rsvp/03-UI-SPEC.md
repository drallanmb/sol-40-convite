# Phase 03 — UI Design Contract

> Visual and interaction contract for the public RSVP flow at `/confirmar`. Generated by `gsd-ui-researcher`; approved after checker review on 2026-07-24.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | None — use the existing project-owned Tailwind v4 design system and primitives |
| Preset | Not applicable |
| Component library | Existing `Shell`, `Button`, `Card`, `Field`, and `Toast`; native `fieldset`, `legend`, radio, and `dialog` semantics |
| Icon library | None; do not add one for this phase |
| Font | Alegreya Variable for editorial headings; Gabarito Variable for body, labels, controls, and feedback |

`components.json` is absent, but this is not an unstyled project: `src/index.css` and the shipped primitives already form the approved design system. Phase 03 must not initialize shadcn, introduce registry blocks, or replace those primitives.

### Visual direction

- Reuse the invitation's warm editorial language: cream page, paper card, sand offset shadow, plum ink, orange/coral highlights, serif display copy, and compact uppercase labels.
- The route is calm and task-focused. It may echo the sunset identity through color and the existing Sol wordmark, but it must not reproduce the animated hero or add decorative motion around a form.
- The family form is a paper invitation, not an admin panel: no dashboard chrome, dense tables, generic gray SaaS styling, or account/login vocabulary.
- Status colors are semantic and already defined: `sea` for `vai`, `rsvp-pendente` for `pendente`, and `wine` for `não vai`.

### Reuse contract

| Existing source | Contract |
|-----------------|----------|
| `src/index.css` | Reuse all colors, font families, type tokens, focus ring, durations, and z-index tokens; add no duplicate palette |
| `src/components/ui/Card.tsx` | Base surface for the phone gate and family form |
| `src/components/ui/Field.tsx` | Base field treatment for phone and shared contact |
| `src/components/ui/Button.tsx` | Reuse its anatomy, sizing, transitions, quiet action, and `aria-busy` behavior; adapt/extend the primary visual treatment for RSVP because the shipped orange/cream primary pairing cannot be reused unchanged at small text |
| `src/components/ui/Toast.tsx` | Transient save feedback only; never the sole source of state |
| `src/components/layout/Shell.tsx` | Shared header, skip link, main landmark, and footer; no countdown rail on `/confirmar` |
| `src/components/invite/Hero.tsx` | Preserve the existing visual composition while changing the action area to two entry actions |
| `src/content/event.ts` | Canonical source for route labels, navigation targets, RSVP copy, and deadline text |

## Typography

Use exactly these four roles and only two font weights (`400` and `700`) in the new RSVP UI:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | Existing `text-body` token: 16–18px fluid | 400 | 1.62 |
| Label | Existing `text-small` token: 15px | 700 | 1.3 |
| Heading | Existing `text-subheading` token: 24–28px fluid | 400 | 1.2 |
| Display | Existing `text-heading` token: 48–78px fluid | 400 | 1.02 |

- Display and Heading use Alegreya; Body and Label use Gabarito.
- Labels and actions may use `tracking-label`, uppercase, at 15px.
- Display copy uses `tracking-display`; never render form labels in the display font.
- Guest names use Heading at weight 400. Long names wrap; they are never ellipsized.
- Do not introduce a third weight for selected choices. Selection is expressed by radio state, border, background, and text contrast.

## Screen Anatomy

### Shared route frame

1. Sticky shared header.
2. RSVP route section on cream.
3. Editorial introduction:
   - Kicker: **“CONFIRMAÇÃO DE PRESENÇA”**
   - `h1`: **“Esse pôr do sol tem lugar pra vocês.”**
   - Required deadline line: **“Confirme até 30 de setembro”**
   - Supporting line: **“Você pode responder agora e editar depois, sem criar conta.”**
4. State-owned card:
   - session restoration;
   - phone gate; or
   - unlocked family form.
5. Existing footer.

The deadline line remains visible before and after 30 September and never changes into a closed/disabled message. After the date, append the quiet clarification **“O prazo passou, mas você ainda pode responder ou editar.”** The server and UI continue to allow save.

### Phone gate

The card contains:

1. Heading: **“Vamos encontrar seu convite.”**
2. Body: **“Digite o telefone usado no convite. Não precisa criar conta.”**
3. `Field`:
   - Label: **“Telefone”**
   - `type="tel"`, `inputMode="tel"`, `autoComplete="tel"`
   - Placeholder: **“(79) 99999-9999”**
   - Hint: **“Inclua o DDD. Pode digitar com ou sem espaços e pontuação.”**
4. Inline message region reserved under the field, associated through `aria-describedby`.
5. Full-width primary action: **“Buscar convite”**, using the accessible RSVP plum/cream primary treatment rather than the existing orange primary variant unchanged.
6. Privacy note: **“O telefone serve apenas para localizar este convite.”**

No family name, person name, canonical phone, RSVP ID, or session detail appears before a successful unlock.

### Family form

The unlocked view contains:

1. Family greeting:
   - Kicker: **“SEU CONVITE”**
   - Heading: **“Olá, {displayName}. Esse pôr do sol tem lugar pra vocês.”**
2. Visible saved summary: **“Vai: {yes} · Não vai: {no} · Pendente: {pending}”**.
3. Quiet session action: **“Usar outro telefone”**.
4. Form heading: **“Quem deste convite estará com a gente?”**
5. Vertical guest list.
6. One optional shared contact field.
7. Persistent inline save-status region.
8. Full-width primary action: **“Salvar respostas”**, using the accessible RSVP plum/cream primary treatment rather than the existing orange primary variant unchanged.
9. Privacy note: **“Seu contato fica só com a organização da festa.”**

### Per-person attendance group

Each person is a visible `fieldset`. The person's full name is the visible `legend`. The group contains three native radio choices in this order:

1. **“Vai”**
2. **“Pendente”**
3. **“Não vai”**

Contract:

- `pending` is a real, selectable value, not an unselected accident.
- Initial radio state mirrors the current server snapshot.
- A change marks only that person dirty.
- Selected controls use their semantic solid background with cream text; unselected controls use card/transparent background, ink text, and `line` border.
- Native checked state or an equivalent visible radio dot remains present, so color is supplemental.
- Every label is at least 44px high and the entire label is clickable.
- The row never truncates a person's name. At narrow widths, choices move below the name.

### Shared contact

- Label: **“WhatsApp ou e-mail para contato (opcional)”**
- Placeholder: **“Para qualquer aviso importante”**
- Hint: **“Seu contato fica só com a organização da festa.”**
- Maximum: 120 characters.
- Do not apply an email-only or phone-only input mask. Preserve the user's content except surrounding whitespace.
- Clearing a previously saved value is an intentional dirty change; leaving the field untouched means unchanged.

## Interaction and State Machine

```text
route mount
  → restoring session
    → valid token: family form
    → no token: phone gate
    → unknown/expired token: expired notice → phone gate

phone gate
  → unlocking
    → found: family form
    → invalid/not found: phone gate with inline error
    → rate limited: phone gate with retry state
    → network/server failure: phone gate with retry

family form
  → editing (dirty subset)
  → saving
    → saved complete
    → saved partial
    → rate limited, draft retained
    → network/server failure, draft retained
    → session expired, capability cleared → phone gate
```

### Session restoration

- Read the versioned RSVP capability from `sessionStorage` once on mount before deciding which card to show.
- While restoration is unresolved, do not flash the phone gate or a not-found message.
- Show the static Shell and a card with the Sol symbol as decorative (`alt=""`), the status **“Reabrindo seu convite…”**, and three neutral skeleton rows.
- Put `aria-busy="true"` on the state card and expose **“Reabrindo seu convite…”** through a polite live region.
- A valid token opens the current server snapshot. A missing token opens the phone gate. An unknown, malformed, or expired token is removed and opens the phone gate with the expired-session notice.
- Reload in the same tab restores. A new tab/browser session without the capability starts at the phone gate.

### Unlocking

- Submit on button activation or Enter from the phone field.
- During the request, keep the entered phone visible; set button text to **“Buscando…”**, set `aria-busy="true"`, and prevent duplicate submit.
- Client-side empty/obviously incomplete input uses **“Digite um telefone com DDD.”** and focuses the phone field.
- Server invalid/not-found outcomes share the generic public copy defined below. Do not reveal whether formatting, invitation data, or a disabled record caused the miss.
- On success, replace the card state without a route change, announce **“Convite encontrado.”**, and move focus to the family greeting heading.

### Editing

- Maintain the latest server snapshot, local draft, and dirty guest/contact set separately.
- A person can move between all three statuses, including back to `Pendente`.
- Partial save is always available; pending people never produce a validation error.
- The saved summary reflects the server snapshot. While dirty, add the suffix **“· alterações ainda não salvas”** in text, not only color.
- When nothing is dirty, show **“Tudo salvo”** in the inline status region and render the submit action disabled.
- The shared contact and per-person choices remain usable by keyboard and touch in source order.

### Saving and partial-save feedback

- During save, button text is **“Salvando…”**, `aria-busy="true"`, and duplicate submit is blocked. Do not clear the draft.
- A successful save:
  - reconciles from the returned/reactive server snapshot;
  - clears dirty markers;
  - leaves focus on the save button;
  - updates the persistent inline summary; and
  - emits the existing `Toast` as a secondary polite announcement.
- Complete response with at least one `Vai`: **“Presenças salvas. Que alegria ter vocês com a Sol!”**
- Complete response with everyone `Não vai`: **“Respostas salvas. Obrigada por avisar com carinho.”**
- Partial response: **“Respostas salvas. Ainda há {pending} pessoa(s) pendente(s) — você pode voltar e completar depois.”**
- The inline message remains until the next edit. The toast may dismiss after the established timeout, but completion is never toast-only.
- Idempotent/repeated save does not invent a different success state or duplicate a family.

### Using another phone

- If there are no unsaved changes, **“Usar outro telefone”** immediately clears the browser capability and returns to the empty phone gate.
- If there are dirty changes, open a native accessible dialog:
  - Heading: **“Descartar alterações?”**
  - Body: **“Você tem respostas que ainda não foram salvas. Quer usar outro telefone mesmo assim?”**
  - Safe action: **“Continuar editando”**
  - Destructive action: **“Descartar e usar outro telefone”**
- Initial dialog focus goes to **“Continuar editando”**. Escape closes and returns focus to **“Usar outro telefone”**.

## Focus, Accessibility, and Input Contract

- Use native landmarks, headings, `form`, `fieldset`, `legend`, radio inputs, buttons, and links.
- Every input has a persistent visible label. Placeholder text is never the label.
- Phone errors connect to the field through `aria-describedby`; invalid state sets `aria-invalid="true"`.
- Inline errors use `role="alert"` only when newly produced. Save success/count updates use a polite status region.
- Each guest's radio group accessible name is **“Presença de {name}”**. Choice accessible names are the visible **“Vai”**, **“Pendente”**, and **“Não vai”**.
- All interactive targets are at least 44×44px with at least 8px separation where targets do not share a segmented-control edge.
- Reuse the global coral focus-visible ring for ordinary controls. RSVP primary actions are the targeted exception: use a 3px sea `#1F4650` focus-visible outline with 3px offset around the plum/cream button. Never remove outlines.
- Do not auto-focus the phone input on initial page load; route focus belongs on the `h1`. Focus the phone input only after a validation error or expired-session transition.
- Do not move focus for save success or failure. Announce the result in place.
- The dirty-discard dialog uses native modal semantics, a labelled heading, controlled initial focus, Escape behavior, and focus return.
- Busy copy is textual; no spinner is required. If a spinner is added, it is `aria-hidden` and the busy text remains.
- No attendance state depends on color. Checked state, visible text, border/fill change, and the textual summary all agree.
- Guest/family data renders as ordinary React text. No raw HTML.
- No raw phone, contact, token, or RSVP identifier is rendered into debugging text, URLs, analytics attributes, or the DOM.
- At 200% zoom and 320px CSS width, the page has no horizontal scroll and every choice remains operable.
- Reduced-motion users receive immediate state changes; nothing essential is conveyed through animation.
