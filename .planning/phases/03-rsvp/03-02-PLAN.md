<objective>
Implement the secure public RSVP backend: capability issuance by phone, one-family scoped read, atomic sparse/idempotent save, and tested server-side rate limits.

Purpose: The phone is intentionally only a light access key. This plan confines the unavoidable low-entropy lookup risk behind rate-limited mutation state, then replaces the phone with a high-entropy, hashed, expiring capability for every subsequent read/write.

Output: three validated public functions (`unlockByPhone`, `getCurrent`, `saveResponses`), centralized security/rate helpers, exhaustive Convex integration tests, regenerated APIs, and a real Convex smoke.
</objective>

## Fixed public contracts

| Function | Input | Safe result |
|----------|-------|-------------|
| `unlockByPhone` mutation | raw phone + fresh 32-byte base64url token | `unlocked`, generic `not_found`, `token_conflict`, or `rate_limited { retryAfterSeconds }`; no family/contact/IDs |
| `getCurrent` query | opaque token | scoped family view or `null`; malformed/unknown/expired are indistinguishable |
| `saveResponses` mutation | token + sparse opaque refs + contact command | `saved { view }`, `session_expired`, `invalid_update`, or `rate_limited { retryAfterSeconds }` |

Expected business outcomes return discriminated values rather than throwing after rate consumption, so not-found/invalid attempts do not roll back their limiter transaction. Unexpected invariant/programming failures may throw without sensitive payloads.

Convex `args` validation necessarily rejects calls whose outer shape never enters the handler. For **every well-formed call that reaches the handler**, make the global save bucket the first authorization-independent control:

1. non-consumingly check the global bucket;
