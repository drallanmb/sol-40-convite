Create `src/components/invite/Countdown.tsx` exporting a `Countdown` component with no props. It calls `useCountdown()` itself and renders the whole countdown section.

The section is a dark full-bleed block: plum background, cream text, with the responsive clamp section padding the UI-SPEC declares as its one deliberate divergence from the fixed spacing tokens — roughly `clamp(80px, 10vw, 160px)` vertically and `clamp(24px, 7vw, 110px)` horizontally, expressed as Tailwind arbitrary values. Inside, a centred max-width container lays the copy block and the tiles side by side on desktop and stacks them on mobile, bottom-aligned when side by side.

The copy block renders the kicker and heading for the current phase, both read from `COUNTDOWN_COPY[phase]` — never hardcoded in this file. The kicker uses the label role: caption size, bold, uppercase, `tracking-label`. The heading is an `h2` in the heading role: `font-serif`, `text-heading`, `tracking-display`. For the pre-event state the heading is two parts — the lead text followed by the emphasised word wrapped in an `em` carrying `not-italic` plus the coral accent, which is this project's established emphasis idiom. For the other three states the heading is a single string.

Branch the body on `COUNTDOWN_COPY[phase].showTiles`. When it is false — the day-of and during-the-party states — render only the heading and, for the during state, its sub-line; render no digits at all. That is deliberate: the owner's own framing for reaching zero is the words, not a row of zeroes.

When it is true — before and after the party — render four tiles from `parts`, in the order days, hours, minutes, seconds. Each tile shows the number and, beneath it, the unit label obtained by calling `pluralizeUnit(count, unit)`. Do not write a unit word as a literal anywhere in this file and do not reimplement the singular/plural rule inline: the countdown passes through one for every unit on its way down, and a second copy of that rule in this file would drift from the tested one.

Size the day tile for growth. The post-party state counts up with no ceiling, so the day number reaches four digits within a few years and the old layout assumed two. Apply `tabular-nums` to the numerals so digits do not jitter as they tick, and give the tile a minimum width sized to comfortably hold four digits at the tile's font size. Do not zero-pad the day value to a fixed two characters — that would either truncate or fight the min-width once the number outgrows it.

Add `aria-live="off"` (or leave the region out of the live-region system entirely) on the ticking numbers: a value that changes every second is hostile to a screen reader if announced. The heading and kicker carry the meaning; the digits are supplementary.

Wrap the section with the id from `SECTION_IDS` only if the topbar links to it — per the locked nav set it does not, so no anchor id is required here.

One last constraint on the post-party state: `COUNTDOWN_COPY.depois.heading` is owner-dictated literal copy and ships exactly as authored, all caps and punctuation included. Render it and nothing else — do not add an explanatory sentence, a softening subtitle, or any further remark aimed at the guest who did not come. The single line is the whole joke.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04-A | Tampering (client-side, self-inflicted) | System clock feeding `getEventState` | low | accept | A guest with a wrong or deliberately altered device clock sees a wrong countdown. There is no server on this route to authoritatively correct it, and the consequence is cosmetic — the invite's date is printed in plain text in the hero eyebrow, footer and `index.html` title regardless of what the timer says. Accepted for this phase; a server-anchored clock would be disproportionate for a party invite. |
| T-02-04-B | Denial of Service (user-facing) | `setInterval` in `useCountdown` driving two renderers | low | mitigate | Two components consume the same hook, so a naive implementation could schedule two intervals. Mitigated structurally: both mount inside one page and each hook instance clears its own interval on unmount (proven by the plan 02-01 acceptance criteria requiring exactly one `setInterval` and a matching `clearInterval`). The end-of-phase manual check walks navigating away and back to confirm no timer growth. |
| T-02-04-C | Information Disclosure | Countdown external requests | low | accept | The countdown makes no network call — all math is local and all copy is bundled. No third-party origin is contacted. Accepted. |
</threat_model>
