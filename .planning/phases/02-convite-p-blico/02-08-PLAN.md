# Plan 02-08 (gap closure): Responsive hero palm sizing

<objective>
Close UAT gap G-02-3: make the hero palm silhouettes responsive so they frame from the
edges at every width instead of overlapping the hero copy on small phones. Mobile-only
correction in `src/components/invite/PalmSvg.tsx` — do not touch Hero.tsx composition,
the SVG path geometry, the sea, or index.css. Preserve the desktop appearance exactly.
</objective>

<tasks>

<task number="1" name="Make palm footprint responsive without regressing desktop">
The single change site is the wrapper `<svg>` className in `src/components/invite/PalmSvg.tsx`
(currently around line 28):

```
className={`pointer-events-none absolute bottom-[-130px] z-[2] h-[600px] w-[360px] drop-shadow-[...] ${positionClasses}`}
```
and `positionClasses` (around line 22):
```
side === 'left' ? 'left-[-82px]' : 'right-[-82px] scale-x-[-1]'
```

Replace the FIXED `h-[600px] w-[360px]` and the fixed `left/right-[-82px]` offsets with
responsive Tailwind classes so that:

- **Mobile (base, <640px):** the palm is smaller and/or pushed further off-edge so its
  fronds clear the central copy column. Concretely, the palm must not overlap the horizontal
  center third of the hero at 360px. A good starting point is roughly `h-[380px] w-[228px]`
  with the trunk anchored closer to the edge (e.g. `left-[-64px]` / `right-[-64px]`), then
  tune so nothing crosses the copy at 360px. Keep `bottom` adjusted proportionally if needed
  so the trunk still meets the horizon.
- **`sm:` (>=640px):** an intermediate size (e.g. ~`sm:h-[500px] sm:w-[300px]`).
- **`md:` and up (>=768px):** restore the ORIGINAL `md:h-[600px] md:w-[360px]` and the
  original `md:left-[-82px]` / `md:right-[-82px]` so the 768px+ and 1440px hero is
  byte-for-byte the same framing as before this plan.

Keep `pointer-events-none`, `absolute`, `z-[2]`, `scale-x-[-1]` (right side), the drop-shadow,
and the `viewBox="0 0 360 600"` UNCHANGED — only the rendered width/height/offset scale by
breakpoint. Do NOT alter any SVG `<path>` geometry, strokeWidth, or the two-sided asymmetry.

Exact pixel values are a means, not the goal: the acceptance test is visual clearance at
360px + identical framing at >=768px. Adjust the numbers until both hold.
</task>
