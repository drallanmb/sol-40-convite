# Phase 4 — UI Design Contract

> Visual and interaction contract for the public wine-gift catalog. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Existing project primitives + Tailwind CSS v4; no shadcn |
| Preset | Not applicable |
| Component library | Project-owned `Button`, `Card`, `Toast`, `Shell`; semantic HTML for catalog-specific components |
| Icon library | None; use text, CSS shapes, or the existing Sol mark—do not add an icon package for this phase |
| Font | Alegreya Variable for editorial headings; Gabarito Variable for body, labels, prices, status, and controls |

`components.json` is absent, but this is not an unstyled React project: Phase 1 already established a project-owned design system and Phase 2/3 built the public shell and primitives on it. Phase 4 extends that system instead of introducing shadcn or a parallel visual vocabulary.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `xs` | 4px | Inline micro-gaps, code/status detail |
| `sm` | 8px | Compact metadata gaps |
| `md` | 16px | Default card/control gap |
| `lg` | 24px | Card padding, mobile page gutters |
| `xl` | 32px | Component groups and tablet gutters |
| `2xl` | 48px | Intro groups and band separation on mobile |
| `3xl` | 64px | Major section separation |

Exceptions:

- `12px` is allowed only for the existing project `--space-sm` rhythm inside metadata groups.
- Every control, shortcut, navigation link, and CTA has a minimum target of `44px`.
- Sticky topbar remains `72px` high.
- Focus geometry may use `1px`/`3px` border widths, `3px`/`6px` outline offsets, and `1px` separators; these are non-layout measurements.
- Main content uses `24px` mobile gutters, `32px` tablet gutters, and `64px` desktop gutters.
- Page and catalog content cap at `1320px`; editorial copy caps at `62ch`.

## Typography

Use exactly two weights in this phase: regular `400` and bold `700`. Italic editorial copy may use synthetic italic at weight `400`; do not introduce `500` or `600`.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / caption | 13px | 700 | 1.35 |
| Body / control / description | 16px | 400 or 700 | 1.62 body, 1.5 description, 1.25 control |
| Heading / wine name | 28px | 400 | 1.08 |
| Display | 48px | 400 | 0.95 |

Additional rules:

- Labels, code, producer, shortcut text, and status use Gabarito, uppercase where specified, with existing `0.1em` label tracking.
- Page and section headings use Alegreya with `-0.025em` display tracking.
- Wine descriptions use Alegreya, `16px` at all widths, weight `400`, line-height `1.5`; do not wrap them in decorative quotation marks.
- Price uses Alegreya `28px/1`, weight `400`, tabular numerals where supported.
- Product names, producers, descriptions, and CTA labels wrap naturally; use `overflow-wrap:anywhere` for names/producers and never truncate commercial content.

## Information Architecture

### `/presentes`

Render in this order:

1. Shared `Shell` topbar, with a gifts-specific navigation set: `Convite`, `Confirmar presença`, `Programação`, `Local`.
2. Compact cellar intro.
3. Operational note.
4. Three band shortcuts.
5. Catalog with all three bands open.
6. Existing shared footer.

The compact intro is `360px` minimum on mobile and `420px` minimum on desktop, including its note and shortcuts. It must never reproduce the old `640–720px` cellar hero. Use `64px 24px 48px` internal spacing on mobile, `64px 32px` on tablet, and `64px` on desktop, measured below the shared topbar. The first band heading should enter or sit immediately below the initial viewport at common laptop heights.

Use a solid cellar surface with one restrained decorative sun: a `160px` mobile / `240px` desktop peach circle at no more than `18%` opacity, partially cropped at the upper-right. No gradient is required, no bottle illustration appears in the intro, and decoration is `aria-hidden`.

### Home preview

Insert the dark cellar preview immediately after `Countdown` and before `LocalSection`; the existing relative order of Local → Guide → Programa → Traje remains unchanged.

The section uses `64px 24px` padding on mobile, `64px 32px` on tablet, and `64px` on desktop. It contains the kicker, heading, support, exactly three fixed cards, then `Ver a carta completa`. Lock the featured set and order to:

1. `39778` — Catena Malbec 2024 — rubi — R$ 222,69
2. `39158` — Famille Perrin Côtes-du-Rhône Réserve Blanc 2024 — dourado — R$ 250,29
3. `39470` — Soalheiro Alvarinho 2024 — verde — R$ 313,01

These remain visible and in this order after status changes. Each entire preview card is one semantic route link to `/presentes#vinho-{código}`; it contains no WhatsApp link or nested interactive control. Its accessible name includes wine name, formatted price, and `Já escolhido com carinho` when applicable.

The home preview uses the same neutral bottle silhouette and the same two-color palette returned for each product as `/presentes`; it must not maintain a second palette map. Because there are exactly three featured products, the preview remains 1 column mobile, 2 columns tablet, and 3 columns from `1024px` upward—never a four-column grid with an empty slot.

### RSVP integration

After the first backend-confirmed `result.kind === "saved"` in the mounted family session, append a persistent cream/sand bordered callout below the save feedback and submit action. It remains visible through later edits and all attendance combinations, including all guests answering “não vai”. Do not render it on initial load, restored-clean state, rate-limit, connection failure, invalid session, or any other non-success outcome.

The callout uses the exact post-save heading/body/CTA above and links to `/presentes`. It does not imply reservation or purchase.

## Catalog Layout and Component Contract

### Band navigation

- Shortcuts are an unordered list inside a `nav` labelled `Escolha por faixa de valor`.
- Use the three exact band labels; each is a same-page anchor to `#faixa-ate-200`, `#faixa-200-350`, or `#faixa-350-500`.
- Targets and cards use `scroll-margin-top:calc(72px + 24px)` to clear the fixed `72px` sticky header plus one declared `24px` spacing token.
- Shortcuts are one wrapping row on desktop and a horizontally scrollable, snap-aligned row on screens below `640px`; the row itself has no hidden controls and shows the next chip edge as an overflow cue.
- Each chip is at least `44px` high, pill-shaped, cream border/transparent surface, and reverses to cream/cellar on hover or keyboard focus.

### Bands

- Keep all three bands mounted and open; no accordion, tabs, filtering, pagination, or virtualization.
- Bands are separated by `64px` at every breakpoint.
- Each heading row contains eyebrow + `h2` on the left and the live `N rótulos` count on the right; stack count below the heading under `480px`.
- Counts are based on returned records and therefore stay stable when a status changes. Use singular `1 rótulo` and plural `N rótulos`.
- Within each band preserve Convex order: price ascending, then product code. Never move gifted items to the end.

### Grid

| Viewport | Columns | Gap |
|----------|---------|-----|
| `< 768px` | 1 | 16px |
| `768–1023px` | 2 | 16px |
| `1024–1279px` | 3 | 24px |
| `>= 1280px` | 4 | 24px |

No horizontal page overflow is allowed at `320px`. Grid width is `100%` inside the `1320px` cap.

### Wine card

- Semantic root: `<article id="vinho-{código}" tabIndex={-1}>`, labelled by its wine-name heading.
- Minimum height: `540px` mobile and `580px` at `768px+`; available cards use flex/grid so CTAs align at the bottom of a row without clipping long copy.
- Surface: cellar-soft, `1px` cellar-line border, square corners to match the editorial grid; `24px` padding at every breakpoint.
- Internal order: authored bottle visual → status and price → `h3` name → producer → description → product code → action/status footer.
- Visual stage: `264px` high, full card width, with a centered `180px` halo mobile / `204px` desktop split into the product's two muted colors. A single project-owned neutral silhouette fits within `116px × 232px` mobile / `132px × 248px` desktop; keep cap/base inside the stage and do not vary geometry by product.
- Price is visually strongest metadata. Product code is visible but quiet: caption size, cream at `72%`, no tracking wider than label tracking.
- CTA is a semantic external `<a>`, full card width, at least `48px` high, cream border, cream text. Hover/focus reverses to cream background/cellar text. Use `target="_blank"` and `rel="noopener noreferrer"`.

### Available and gifted states

Available card:

- Show `Disponível`, formatted price, and `Presentear pelo WhatsApp`.
- Clicking the CTA performs no mutation, optimistic update, reservation, toast, or confirmation modal.

Gifted card:

- Keep the same position, dimensions, commercial copy, code, price, silhouette, and product palette.
- Remove the WhatsApp anchor from the DOM—do not render a disabled button.
- Render `Já escolhido com carinho` in gifted green with a visible `1px` border.
- Soften only the bottle stage (`filter:saturate(.45)`, `opacity:.68`) and secondary description (`cream` at `70%`). Keep the name, price, code, and status at AA contrast.
- State is conveyed by literal text plus absent action, never opacity or color alone.

If a reactive update changes a focused available card to gifted, move focus to the card article, announce `Já escolhido com carinho` politely, and leave scroll position unchanged.

## Label Palette & Bottle Silhouette Contract

Final Phase 4 acceptance uses one authored, reusable bottle silhouette and 37 product-specific palette records:

- The silhouette is implemented locally in SVG/CSS/React and owned by the project. It may follow the approved composition reference at `/Users/allanmesquitabrito/.codex/generated_images/019f9644-e00b-7f73-85a6-5f70928442f4/call_M6hysFZ2GBdBeROsuWq63oMA.png`: dark neutral bottle, blank abstract label area, and a two-part circular halo.
- The silhouette contains no producer logo, brand typography, copied label art, bottle photography, trademarked decorative motif, or readable invented label text. It makes no claim that bottle shape, glass, capsule, or label is a faithful depiction of the product.
- The silhouette geometry is identical for all 37 products. Product differentiation comes from commercial text and the two-color halo, never from copied product artwork.
- Every canonical `productCode` has exactly two distinct CSS hex colors (`#RRGGBB`), selected as muted decorative interpretations inspired by colors visible on an official producer page, official retailer/product page, or reputable commercial catalog.
- Every palette record stores an `https://` reference URL and consultation date for audit. These are provenance metadata only: the application does not render the URL, request the remote image at runtime, or expose it as an image source.
- Colors may be sampled/approximated by visual inspection, then muted and adjusted to suit the cellar surface. Do not copy layouts, gradients, logos, illustrations, typography, or distinctive label compositions.
- Validate all 37 mappings: unique canonical code, two valid/distinct hex strings, safe `https://` provenance URL, non-empty date, and no missing product.
- The public DTO returns only the two palette colors required to render. It omits provenance URL/date and legacy `imageUrl`. `Presentes.tsx` validates those two colors instead of the removed image field.
- Persisted rollout is two-stage: first publish the four new fields as optional beside optional legacy `imageUrl`, reconcile and verify all 37 rows, then make palette/provenance required in the final schema. Public queries fail closed for an incomplete transitional row.
- The historical `imageUrl`, `public/wines/manifest.json`, `scripts/audit-wine-assets.mjs`, and `audit:wine-assets` script are not final requirements. Remove them through a narrow staged diff after tests prove no runtime/build reference remains.

The visual is deterministic local markup, so there is no image loading, broken-image, alpha, crop, intrinsic-dimension, byte-budget, lazy-loading, or rights-holder-photo state. The fixed visual-stage dimensions themselves prevent layout shift.

## Deep-Link Contract

- Stable URL: `/presentes#vinho-{productCode}`. Product code remains a string so `0699230` is preserved.
- Validate the hash through a pure helper; never inject raw fragment text into a selector.
- Once the asynchronous catalog exists, find the matching article, call `scrollIntoView({ block: "center", behavior })`, then focus it with `{ preventScroll:true }`.
- `behavior` is `smooth` only when reduced motion is not requested; otherwise `auto`.
- The selected card gets a persistent `3px` peach outline with `6px` offset and the visible label `Rótulo selecionado`. This provides a non-color cue in addition to focus.
- Direct load, home navigation, refresh, browser back/forward, and a gifted target must all work.
- An unknown or malformed fragment produces no error, no announcement, and no unsafe DOM lookup; render the normal page start.

## Loading, Error, Empty, Partial, and Visual States

### Catalog loading

- Keep compact intro, note, and band navigation visible.
- Render all three band headings and, inside each band, one full responsive row of non-animated skeleton cards: 1 mobile, 2 tablet, 3 desktop at `1024–1279px`, and 4 at `>=1280px`.
- Skeletons preserve card and visual-stage dimensions, use cream at `6–12%`, and have no shimmer.
- Put `aria-busy="true"` on the catalog region and announce `Carregando a carta de vinhos…` once through a screen-reader status.

### Home loading

- Preserve the full section height and render exactly three card skeletons in the same 1/2/3 responsive grid.
- Heading/support and `Ver a carta completa` remain visible; the CTA may navigate to the complete page while preview data is loading.

### Query error

- Replace only the affected catalog/preview grid with a bordered inline panel.
- Use the exact error copy and `Tentar novamente`; retain page heading and navigation.
- The message has `role="alert"`. Retry repeats the read or reloads the route without changing the URL fragment.

### Empty catalog

- Render the exact empty heading/body in the catalog region and no band shortcuts, cards, counts, or WhatsApp links.
- Keep page intro and operational note visible.

### Empty or partial band

- A band with zero records remains in document order and shows the exact empty-band body.
- Missing producer/description/code/price is not a valid display state: the public DTO validator must reject malformed rows. If one record is rejected or unavailable while others load, render the valid cards, show one non-blocking error panel at the catalog top, and never invent missing commercial data.

### Zero, one, or many

- One returned card occupies one normal grid column; it does not stretch across the row.
- Thirty-seven cards render without virtualization.
- Status changes do not alter counts, position, or section height.

## Interaction and Motion

- Base transitions use existing `180ms` fast timing and project ease-out.
- Available card/preview hover on fine pointers may translate `-4px`; keyboard focus uses outline without requiring movement.
- CTA active state scales to `0.98`.
- Deep-link scroll is the only smooth scroll introduced by this phase. Selected outline/label appears in `260ms`; no flashing or pulsing.
- Silhouettes and halos do not float, rotate, parallax, or autoplay.
- Under `prefers-reduced-motion: reduce`, disable smooth scroll, hover translation, scale, and selected-state transition; all content and state cues remain visible.

## Accessibility Contract

- Use one page `h1`; bands use `h2`; wine names use `h3`. Home preview section uses `h2`, preview wine names use `h3`.
- Every band is a `<section aria-labelledby>`. Catalog and preview loading/error regions have stable accessible names.
- The silhouette and halo are one decorative visual group with `aria-hidden="true"` and no image alt. The adjacent visible wine name, producer, price and code carry the product identity; do not announce a claim of visual fidelity.
- All interactive targets are at least `44 × 44px`; keyboard order follows visual/document order.
- Focus on cellar surfaces uses a `3px` peach outline with `3px` offset. Do not suppress the existing global focus style without replacing it.
- External CTA retains the visible literal label and adds the assistive suffix `Abre o WhatsApp em uma nova aba.` in visually hidden text.
- Reactive status changes use polite announcement; query failures use alert semantics. Do not attach `aria-live` to the full 37-card grid.
- Shortcuts and cards remain usable at 200% zoom and at `320px` width. Text reflows; no commercial copy or CTA is clipped.
- Cream body text, peach labels, and gifted green meet WCAG AA on cellar. Coral is prohibited for normal-size cellar text.
- Gifted state is communicated by text and absent action. Selected deep-link state uses text plus outline.
