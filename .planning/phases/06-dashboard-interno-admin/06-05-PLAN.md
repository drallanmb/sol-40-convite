## Trust Boundaries

| Boundary | Untrusted side | Trusted side |
|---|---|---|
| Public unlock -> RSVP session row | Browser token and invitation lookup | Hash-only row stamped with server-owned expiry/generation |
| Scheduled command -> session deletion | Delayed/retried scheduler delivery | Internal id + expected-expiry comparison |
| Historical table -> migration sweep | Arbitrarily many legacy expired rows | Indexed fixed-size page and opaque continuation |
| Session row -> public family data | Stale, expired, or old-generation capability | Strict expiry and generation check before RSVP projection |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-06-21 | Denial of service | accumulated `rsvpSessions` | high | mitigate | Schedule every new row's expiry and add a bounded daily indexed sweep for historical rows. |
| T-06-22 | Tampering | delayed expiry command | high | mitigate | Delete only when id and `expectedExpiresAt` still match; retries return ignored without write. |
| T-06-23 | Elevation of privilege | old-generation public capability | high | mitigate | Resolve only an active row whose generation equals the current invitation generation, interpreting both legacy omissions as zero. |
| T-06-24 | Denial of service | cleanup continuation | high | mitigate | Fixed page size, indexed cutoff, opaque cursor, and deterministic terminal `done`; no unbounded collect or zero-progress restart. |
| T-06-25 | Information disclosure | lifecycle results | high | mitigate | Keep cleanup functions internal and public DTOs unchanged; never return token hashes. |
</threat_model>
