# Phase 6 — UI Design Contract

> Visual and interaction contract for the protected `/admin` dashboard. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Product Register

This is an operational product surface used repeatedly by Allan and Soraya before and during the event, often on a phone and sometimes under time pressure. Familiar controls, visible state, compact information and error recovery take priority over decorative presentation.

The dashboard preserves the public site's warm sunset identity through color and type, but it is not a miniature invitation page:

- use `Gabarito` for all controls, labels, data and operational headings;
- reserve `Alegreya` for the login title, the sidebar wordmark and the page title only;
- use color to communicate navigation, status and action, never as ambient decoration;
- no hero treatment, animated scenery, oversized metric numerals, glass effects or nested decorative cards;
- do not restore moderator roles, team codes, Instagram, screen/telão, settings, QR, reservations or bulk guest import.

## Design System

| Property | Value |
|----------|-------|
| Tool | Existing project primitives; no shadcn |
| Preset | Not applicable |
| Component library | Project-owned React primitives plus native HTML controls/dialog |
| Icon library | No dependency; one consistent 20px outline SVG set, `stroke-width: 1.75`, `currentColor`, decorative icons `aria-hidden` |
| Fonts | `Gabarito Variable` for product UI; `Alegreya Variable` only for restrained brand/page titles |
| Existing primitives | Extend/reuse `Button`, `Card`, `Field`, `Toast`; do not introduce a second component kit |

### Primitive contract

- `Button`: keep minimum target `44px`. Admin compact actions may use 16px horizontal and 8px vertical padding, sentence case and no tracking; do not inherit the public primitive's uppercase/pill presentation for every action. Add an admin-compatible `secondary` and `destructive` vocabulary rather than styling one-off buttons.
- `Field`: keep visible label and 44px control height. Admin search and select controls use a complete 1px outline, 8px radius and `card` fill; editing forms may keep the existing bottom-border field only where several fields form one continuous panel.
- `Card`: a 16px sand offset shadow is allowed for the single login card. Operational panels use a 1px `line` border with no shadow and 8px radius; never nest a bordered card inside another bordered card.
- `Toast`: extend it to accept an optional action and dismiss control. In authenticated mobile views, position above the bottom bar plus safe area. Use `role="status"` for success/undo and `role="alert"` for failures.
- Dialogs: native `<dialog>` or a focus-trapped portal. Title, consequence, primary/destructive action and a context-specific back action are mandatory. Escape and backdrop close non-destructive dialogs; pending requests prevent duplicate submission.
- Tabs: semantic buttons in a `role="tablist"` only if paired with `role="tabpanel"` and keyboard arrow navigation. Otherwise use route links with `aria-current="page"`. The implementation must choose one model consistently per surface.

## Spacing Scale

Declared values are multiples of 4 and map to existing tokens where possible:

| Token | Value | Existing alias | Usage |
|-------|-------|----------------|-------|
| 2xs | 4px | `--space-2xs` | Icon-to-label micro-gap, status dot gap |
| xs | 8px | `--space-xs` | Compact inline groups, badge inset |
| sm | 8px | — | Row controls, metadata clusters |
| md | 16px | `--space-md` | Default panel/row padding on phone |
| lg | 24px | `--space-lg` | Desktop panel padding, content gaps |
| xl | 32px | `--space-xl` | Page section separation |
| 2xl | 48px | — | Login/page outer spacing |
| 3xl | 64px | — | Maximum desktop page top/bottom space |

Exceptions:

- minimum interactive target: 44px;
- mobile bottom bar: 64px content height plus `env(safe-area-inset-bottom)`;
- desktop sidebar: 248px;
- toast offset: 16px above desktop viewport edge or above the mobile bottom bar;
- 1px borders and 2px/3px focus outlines are not spacing tokens.

### Layout density

- Main content width: `min(100%, 1440px)`; readable forms cap at `720px`.
- Desktop page gutter: 32px from 1024px, 48px from 1280px.
- Mobile page gutter: 16px; tablet gutter: 24px.
- Operational rows: 16px vertical padding at every width.
- Avoid large empty bands: page header to first control/panel is 24px, section-to-section is 32px.

## Typography

Admin typography uses fixed sizes rather than the public site's fluid display scale.

| Role | Family | Size | Weight | Line Height | Tracking |
|------|--------|------|--------|-------------|----------|
| Body | Gabarito | 16px | 400 | 1.5 | normal |
| Compact/meta | Gabarito | 14px | 400 | 1.4 | normal |
| Label/button/tab | Gabarito | 14px | 700 | 1.3 | 0 |
| Row title | Gabarito | 16px | 700 | 1.35 | 0 |
| Section heading | Gabarito | 20px | 700 | 1.25 | -0.01em |
| Page title | Alegreya | 32px | 700 | 1.08 | -0.02em |
| Login title | Alegreya | 32px | 700 | 1.02 | -0.025em |
| Metric value | Gabarito | 32px | 700 | 1.0 | -0.02em |
| Sidebar wordmark | Alegreya | 20px | 700 | 1 | -0.02em |

Rules:

- Operational labels, buttons, tab names and data never use Alegreya or all-caps letter spacing.
- Sentence case for all controls: `Adicionar família`, not `ADICIONAR FAMÍLIA`.
- Use tabular numerals for counts, dates and codes.
- Long family names, guest names, presenter names and wine names wrap at word boundaries; codes and phone numbers do not wrap.
- Clamp only secondary previews: family summary to 2 lines, memory text preview to 6 lines when collapsed. Never truncate text required to make a moderation decision; provide `Ler tudo`.

## Color

The established palette remains canonical.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `cream #fff3df` | Main content background and login canvas |
| Secondary (30%) | `card #fffaf1`, `sand #f6dfc3` | Panels, rows, selected/hovered neutral surfaces, sidebar separators |
| Primary accent (≤10%) | `plum #35192a` | Sidebar, primary actions, selected navigation, toast |
| Warm action accent | `orange #d94f29` | Login/primary confirmation action where plum is already the surrounding surface |
| Focus | `coral #ee6a50` | Global focus outline only |
| Confirmed/success | `sea #1f4650` | Confirmed RSVP, approved state, success icon/text |
| Pending/warning | `rsvp-pendente #8a4a15` | Pending RSVP/moderation, warning copy |
| Refused/destructive | `wine #6d253a` | Refused RSVP and destructive actions |
| Text | `ink #2b1822` | Primary content |
| Border | `line rgba(53,25,42,.18)` | Panel, row and field boundaries |

Accent is reserved for:

- current navigation item;
- primary save/confirm action;
- focus outline;
- status chips/counts;
- badges for actionable pending work;
- destructive confirmation/action.

Do not use accent merely to decorate headings or inactive icons. Do not communicate any state by color alone: every chip includes text, every badge has an accessible label and destructive controls name the action.

### State recipes

| State | Background | Text/border | Label |
|-------|------------|-------------|-------|
| Confirmed / Approved | `sea/10` | `sea` | `Vai` / `Aprovada` |
| Refused / Hidden | `wine/10` | `wine` | `Não vai` / `Oculta` |
| Pending | `rsvp-pendente/10` | `rsvp-pendente` | `Pendente` |
| Gifted | `gifted` at low tint | `cellar` | `Presenteado` |
| Available | `card` | `plum` | `Disponível` |
| Disabled | transparent or `sand/35` | `ink/50` | unchanged text |
| Error panel | `wine/8` | `wine` | icon + problem and recovery action |

All text/background pairs must meet WCAG AA: 4.5:1 for normal text and 3:1 for large/bold text and UI boundaries.

## Responsive Structure

| Range | Shell | Content behavior |
|-------|-------|------------------|
| `< 640px` | Mobile header + fixed four-item bottom bar | Single column; full-width dialogs/sheets with 16px inset; family rows become stacked summaries; action pairs may stack |
| `640–1023px` | Same mobile shell and bottom bar | Two-column overview where space permits; moderation cards may use image/content split; forms remain one readable column |
| `≥ 1024px` | Fixed 248px sidebar; no bottom bar | Content scrolls independently; overview uses compact grid; family and gift rows use aligned columns |
| `≥ 1280px` | Same sidebar | Main gutters grow to 48px; moderation content column can reach 1120px; never stretch forms beyond 720px |

### Mobile safe areas

- Header height is 64px and remains visible at the top; its overflow menu contains `Sair`.
- Bottom bar contains exactly four destinations in this order: `Visão`, `Convidados`, `Moderação`, `Presentes`.
- Bottom bar height is `64px + env(safe-area-inset-bottom)`.
- Main content gets bottom padding equal to the 64px bottom bar plus 24px clearance and `env(safe-area-inset-bottom)` so buttons and last rows are never obscured.
- Toasts and dialogs account for both keyboard and safe area.

## Shell and Navigation Contract

### Desktop sidebar

- Sidebar uses solid `plum`, `cream` text and a subtle `cream/20` divider; no gradient.
- Header: wordmark `Sol 40` and small plain-text subtitle `Painel da festa`.
- Four route links use 44px minimum height, 20px icon, full label and count badge when applicable.
- Active item uses `cream` background and `plum` text; inactive hover uses `cream/10`.
- `Convidados` badge equals the number of pending **people**. `Moderação` badge equals pending memories. Badge `0` is omitted.
- `Presentes` never receives a badge.
- `Sair` is a quiet full-width action pinned to the sidebar footer and visually separated by a divider.

### Mobile header and bottom bar

- Header shows the current page title and a 44px overflow/menu button with
  `aria-label="Abrir menu"` when closed and `aria-label="Fechar menu"` when
  open. Menu contains only relevant utility actions, including `Sair`; it does
  not duplicate the four destinations.
- Bottom links combine icon and short text. Active state uses plum text plus a 3px top indicator or selected background; inactive labels remain readable.
- A badge is positioned beside, not on top of, the icon and announces `N pessoas pendentes` or `N memórias pendentes`.
- Route changes preserve browser history, focus the page heading and scroll content to top unless restoring the exact URL after reauthentication.

### Stable routes and deep links

- `/admin` redirects to `/admin/visao`.
- `/admin/convidados?presenca=pending`
- `/admin/moderacao?status=pendente`
- `/admin/presentes?status=gifted`
- Unknown or invalid query values fall back to each area's default without error.
- Search terms are local ephemeral state and do not need to survive reauthentication. Section and filter do survive because they live in the URL.

## Login and Session Gate

### Checking session

- Before session validity is known, render only the `cream` canvas, centered wordmark and a restrained skeleton/progress label `Verificando acesso…`.
- Do not render shell silhouettes, counts, names, photos, filters or cached protected data.
- The checking state persists for at least one paint to prevent a flash of the login form on valid returning sessions, but has no artificial delay.

### Login composition

- Center one login card at `min(440px, calc(100vw - 32px))`; use the existing offset sand shadow only here.
- Order: `Sol 40` wordmark, title `Painel dos donos`, description `Entre com a senha compartilhada para cuidar da festa.`, password field, error region, primary `Entrar no painel`.
- Password field: `type="password"`, `autocomplete="current-password"`, visible label `Senha`, optional show/hide button with accessible state `Mostrar senha` / `Ocultar senha`.
- Submit on Enter. While authenticating: button text `Entrando…`, `aria-busy="true"`, password input and submit disabled, no duplicate requests.
- Wrong credential retains focus on the password field, selects its content and shows `Senha incorreta. Confira e tente novamente.` in `role="alert"`.
- Rate limit shows `Muitas tentativas. Aguarde um pouco e tente novamente.`; do not expose technical bucket details.
- Network/configuration error shows a retryable message and never implies the password was wrong.
- No link for moderator code, guest phone, Google sign-in or account recovery.

### Expiration and logout

- On server invalidation or the absolute seven-day boundary, unmount all protected views immediately, clear the token and all local drafts, then show login at the same URL.
- Login description changes to `Sua sessão expirou. Entre novamente para continuar nesta seção.` after expiry/revocation.
- After successful reauthentication, render the preserved route/filter and move focus to that page's `h1`.
- Logout enters a pending state `Saindo…`, awaits server revocation, clears local access in every case and returns to login.
- If server revocation cannot be confirmed, show `Você saiu deste navegador, mas não foi possível confirmar o encerramento no servidor. Tente entrar e sair novamente quando a conexão voltar.` No protected data remains visible.
- Cross-tab logout/expiry uses the same transition and copy.

## Overview Contract

### Page hierarchy

- Page title: `Visão geral`.
- Supporting line: `Acompanhe confirmações, moderação e presentes em tempo real.`
- A visually modest live-status label `Atualizado ao vivo` may include a small sea dot; it is not a timestamp or manual refresh control.

### Operational summary

Use one attendance group and two action groups rather than five identical floating cards:

1. `Confirmações` panel with three whole-panel links/segments:
   - `Confirmados` — count by person, destination `presenca=yes`;
   - `Não vão` — count by person, destination `presenca=no`;
   - `Pendentes` — count by person, destination `presenca=pending`, visually prioritized when non-zero.
2. `Memórias pendentes` whole-card link to `status=pendente`.
3. `Vinhos presenteados` whole-card link to `status=gifted`, displayed as `N de 37` when total is available.

Cards/segments have one accessible link target, visible focus around the whole surface and an explicit affordance (`Ver convidados`, `Revisar fila`, `Ver presentes`) without nested buttons. Do not use click handlers on non-semantic `div`s.

### Overview states

- Loading: skeletons preserve the exact final layout; labels may remain visible but no fake counts.
- `familyCount === 0`: explain that no families have been created and link `Adicionar primeira família`.
- `familyCount > 0` with all attendance counts at zero: say `Nenhuma pessoa cadastrada nos convites` and link `Ver famílias`; never infer this state from attendance sums or claim that no family exists.
- Zero pending guests: show `Todos responderam` while the Confirmed and Refused totals remain available.
- Zero moderation queue: show `Nenhuma memória aguardando revisão`.
- No gifted wines: show `Nenhum vinho marcado como presenteado`.
- Query error: replace the affected panel values with `—`, show one page-level error message and `Tentar novamente`; do not preserve stale values as if current.

## Guests Contract

### Page header and tools

- Title: `Convidados`; primary action: `Adicionar família`.
- Search label may be visually compact but remains programmatically present. Placeholder: `Buscar família, pessoa ou telefone`.
- Search is partial, accent/case insensitive, and digit-normalized for phones.
- Presence filters: `Todos`, `Confirmados`, `Pendentes`, `Não vão`; show people counts scoped to the search result. Filter changes announce result count through one persistent polite live region.
- A clear-search button appears only when non-empty and is labelled `Limpar busca`.

### Family list

- One semantic expandable item per family. Use a button heading with `aria-expanded` and `aria-controls`; the entire row is not a toggle if it also contains independent actions.
- Collapsed summary contains:
  - family/display name;
  - formatted phone;
  - `N pessoas`;
  - response summary such as `2 confirmados · 1 pendente`;
  - chevron.
- Presence filters select families containing at least one matching person, then show **all** people inside each matched family. Add helper text near filters: `O filtro encontra famílias; ao abrir, todas as pessoas continuam visíveis.`
- Search matches family, any person or phone; the matching text can be emphasized without changing content or color-only indication.
- Expansion is local UI state. Opening one family does not close another. Provide `Recolher` semantics through the same toggle.

### Expanded family editor

- Family fields form the first section: `Nome da família`, `Telefone`, `Contato` and action `Salvar família`.
- Changing phone shows inline notice before save: `Ao trocar o telefone, os acessos públicos deste convite serão encerrados.`
- People appear as compact rows with name field and a labelled three-option segmented/radio control: `Pendente`, `Vai`, `Não vai`.
- Each person row has `Salvar pessoa` only when dirty and a quiet menu/action for `Remover pessoa`.
- `Adicionar pessoa` is placed after the people list and opens an inline form inside the expanded family, not a prompt.
- Family server updates received while no local field is dirty refresh in place. If local edits are dirty, show a conflict notice instead of silently overwriting.
- Save success does not collapse the family. Announce `Alterações salvas.` in a polite region/toast.

### Create family

- Open a focused dialog on desktop and a full-height sheet/dialog on mobile.
- Required: `Nome da família`, `Telefone`. Optional: `Contato`.
- Include a repeatable `Pessoas` subsection; zero people is allowed. `Adicionar pessoa` adds a row with default state `Pendente`.
- Primary action: `Criar família`; secondary: `Voltar sem criar`.
- Duplicate/equivalent phone error is inline at the phone field: `Este telefone já pertence a outra família.`
- Successful creation closes the dialog, clears its draft, focuses the new expanded family and announces `Família criada.`

### Removal

- Remove person confirmation:
  - title `Remover {nome}?`;
  - body `A pessoa será removida desta família. As outras pessoas e o convite continuam.`;
  - action `Remover pessoa`.
- Remove family is separated below the editor in a `Zona de cuidado`, never adjacent to Save:
  - title `Remover a família {nome}?`;
  - body `Esta ação remove o convite e todas as pessoas e encerra os acessos públicos vinculados. Não é possível desfazer.`;
  - require typing the family name exactly or checking `Entendo que toda a família será removida` before enabling `Remover família`;
  - cancellation gets initial focus; destructive confirmation never does.

### Guests states

- Initial loading: 5 family-row skeletons plus tool skeleton; creation action may remain disabled.
- No families: `Nenhuma família cadastrada` with `Adicione uma família para começar a organizar as confirmações.` and CTA.
- No search result: `Nenhuma família encontrada` with `Tente outro nome ou telefone.` and `Limpar busca`.
- No filter result: `Nenhuma família neste filtro` and `Ver todos`.
- Empty family: expanded item says `Nenhuma pessoa nesta família.` and offers `Adicionar pessoa`; it remains editable/removable.
- Save error: keep draft and show field/domain error plus `Tentar salvar novamente`.
- Stale edit/conflict: `Esta família foi alterada em outra sessão. Suas mudanças não foram salvas.` Actions: `Revisar versão atual` (reload and clear draft after confirmation) and `Copiar minhas alterações` where practical.
- Overflow: list may be long; do not render a separate duplicated mobile tree. Keep one semantic list and paginate/load more only if backend pagination is introduced.

## Moderation Contract

### Structure

- Page title: `Moderação`; supporting line: `Revise memórias antes que apareçam no mural.`
- Tabs and URL values: `Pendentes`, `Aprovadas`, `Ocultas`; include counts when known.
- Pending order is oldest first. Other tabs use most recently moderated first unless backend contract fixes another deterministic order.
- Pending queue uses a single vertical review column; at `≥640px`, each photo card may use a 40/60 media/content split. Do not use a dense thumbnail grid.

### Memory card

- Render full uncropped photo within a bounded neutral frame using `object-fit: contain`; no decision-critical content may be cropped.
- Text-only posts receive an equally clear text surface, not an image placeholder.
- Show author, submission date/time and current state text.
- Long messages render up to 6 lines initially with `Ler tudo`; expanded copy has no arbitrary height cap.
- Pending actions: primary `Aprovar memória`, secondary/destructive-toned `Ocultar memória`.
- Approved action: `Ocultar memória`.
- Hidden action: `Aprovar memória`.
- Each action disables only that card, sets `aria-busy`, retains the card until success, then moves it to the destination tab.

### Undo and concurrency

- Successful transition toast: `Memória aprovada.` or `Memória ocultada.` plus action `Desfazer`.
- Undo window: 8 seconds; visual dismissal may fade over 180ms. Screen-reader users receive the full message and action immediately.
- A successful undo says `Alteração desfeita.`
- Concurrent conflict says `Esta memória foi alterada em outra sessão. Mantivemos a versão mais recente.` The card refreshes to the server state; no automatic overwrite.
- A normal mutation failure leaves the card in place and shows `Não foi possível atualizar esta memória. Tente novamente.`

### Moderation states

- Loading: two large card skeletons with media ratio reserved.
- Pending empty: `Fila em dia` and `Nenhuma memória aguardando revisão.`
- Approved empty: `Nenhuma memória aprovada ainda.`
- Hidden empty: `Nenhuma memória oculta.`
- Image load failure: keep metadata/actions visible and show `Não foi possível carregar esta foto.` plus `Tentar novamente`.
- List/query failure: full-width error panel with `Tentar novamente`; do not display cached hidden/pending content after an authorization error.

## Gifts Contract

### Structure and filtering

- Page title: `Presentes`; supporting line: `Registre os vinhos já presenteados.`
- Tabs and URL values: `Disponíveis`, `Presenteados`, with counts.
- Search placeholder: `Buscar vinho, código ou quem presenteou`.
- Preserve the three canonical price bands as section headings inside each tab, each with item count. Empty bands are omitted unless the entire tab is empty.
- Desktop wine row columns: wine name, Mistral code, price, status/presenter, action. Mobile stacks metadata under the name.

### Mark as gifted

- `Marcar como presenteado` opens a focused dialog tied to the selected wine.
- Dialog repeats wine name/code and requires `Nome de quem presenteou`.
- Primary action: `Confirmar presente`; secondary: `Voltar aos presentes`.
- Do not request date/time; after success display the server timestamp in Brazilian date/time format.
- Successful copy: `{vinho} marcado como presenteado.`
- Validation: `Informe o nome de quem presenteou.`
- A stale revision keeps the dialog open and says `Este vinho foi atualizado em outra sessão. Revise o estado atual antes de continuar.`

### Unmark

- `Desfazer marcação` opens confirmation:
  - title `Tornar {vinho} disponível novamente?`;
  - body `O nome de quem presenteou e a data da marcação serão removidos.`;
  - action `Tornar disponível`.
- Successful copy: `{vinho} voltou a ficar disponível.`
- The action is destructive in consequence but uses `wine` outline, not an alarming full red page treatment.

### Gifts states

- Loading: skeleton groups preserve price-band headings and 4 rows.
- Available empty: `Todos os vinhos foram presenteados` and a link/tab action `Ver presenteados`.
- Gifted empty: `Nenhum vinho presenteado ainda.`
- Search empty: `Nenhum vinho encontrado` with `Limpar busca`.
- Query error: `Não foi possível carregar os presentes.` plus retry.
- Mutation error retains dialog input and allows retry.
- Live updates move a non-edited row between tabs. If its dialog is open, show conflict state and require review rather than closing silently.

## Loading, Error and Protected-Data Rules

| Situation | Required UI behavior |
|-----------|----------------------|
| Session checking | Login-neutral branded loader only; no shell/data tree |
| Protected query loading | Layout-matched skeleton; no fabricated counts/content |
| First-load network failure | Error panel with retry and no stale claims |
| Background reactive reconnect | Keep current authorized data, show non-blocking `Reconectando…`; if authorization becomes invalid, immediately clear it |
| Mutation pending | Disable only affected action/scope, preserve context, label with present-progress verb |
| Mutation failure | Keep draft/card state, plain-language error, retry path |
| Session expired/revoked | Unmount all protected data and drafts before login |
| Concurrent edit | Do not overwrite; identify newer remote state and offer reload/review |
| Empty collection | Explain what the collection is and provide the next valid action |
| Long/overflow content | Wrap human text, preserve codes/phones, provide expansion for memory copy |

No state may fall back to a centered indefinite spinner or the phrase `Algo deu errado`.

## Accessibility Contract

- Every page has one `h1`; expanded family sections use ordered `h2`/`h3` hierarchy.
- Provide a skip link `Pular para o conteúdo` as the first focusable element after authentication.
- Sidebar and bottom bar use `<nav aria-label="Seções do painel">`; active route uses `aria-current="page"`.
- All target sizes are at least 44×44px with at least 8px separation between destructive and adjacent actions.
- Global focus remains the existing 2px coral outline with 3px offset; on plum surfaces use a cream inner/outer treatment if coral contrast is insufficient.
- Search results, filter result counts, saves, tab-moving actions and undo outcomes are announced once, not by multiple competing live regions.
- Errors tied to fields use `aria-describedby`; form summary errors focus the first invalid field.
- Dialogs trap focus, set `aria-labelledby`/`aria-describedby`, restore focus to the invoker and place initial focus on the safest useful control.
- Expand/collapse controls expose `aria-expanded`; chevrons are decorative.
- Tabs support Left/Right, Home and End when implemented as ARIA tabs.
- Status badges always include text or an accessible name; charts are not required for overview counts.
- Photos have contextual alt text such as `Memória enviada por {autor}`. Decorative wine visuals are hidden from assistive technology.
- Respect 200% browser zoom without horizontal page scrolling at 320 CSS px. A row may scroll internally only for an actual data table, but this contract prefers responsive stacked rows.
- `prefers-reduced-motion: reduce` disables movement and uses instant state replacement or short opacity-only feedback.

## Motion and Feedback

- Default transition: existing `--duration-fast` 180ms with `--ease-out`.
- Panel/dialog entrance: 180ms opacity + maximum 8px translate; no spring, bounce or stagger.
- Expand/collapse: use content disclosure with 180ms opacity/transform only if height can remain accessible; otherwise open instantly. Do not animate unknown `height`.
- Row movement between reactive tabs is not animated across layouts. Fade the affected card for 120–180ms, then update.
- Button active state may scale to `0.98`; disabled/loading controls do not pulse.
- Skeleton shimmer is optional; if used it is subtle, stops under reduced motion and never masks readable labels.
- No page-load choreography or decorative continuous animation in `/admin`.
